# RAG Architecture Implementation Summary

## Overview

You asked for a **RAG (Retrieval-Augmented Generation)** architecture so you don't have to hardcode rules for every query. I've implemented a complete semantic search system that:

✅ **No more hardcoding** — Replace keyword matching with intelligent semantic search
✅ **Works offline** — TF-IDF vectorizer requires no external API calls
✅ **LLM-ready** — When you add OpenAI or Groq keys, the LLM augments responses with retrieved data
✅ **Extensible** — Just add new data sources to `rag.py` and they're automatically indexed

## What Changed

### New Files

- **`app/rag.py`** — RAG engine:
  - `RAGStore` class builds a semantic search index over all dataset records
  - Supports two backends:
    1. **TF-IDF** (default, always works) using scikit-learn
    2. **Sentence-Transformers + FAISS** (optional, better quality if HuggingFace is accessible)
  - `search(query)` returns top-K semantically similar records
  - `retrieve_context_snippets(query)` groups results by type (companies/contacts/deals/emails)

- **Test scripts:**
  - `test_rag_init.py` — Verify RAG initialization
  - `test_rag_snippets.py` — Debug snippet retrieval for queries
  - `test_agent_rag.py` — End-to-end agent test

### Modified Files

- **`app/agent.py`**:
  - Replaced `_gather_context_snippets` to use RAG instead of keyword matching
  - Updated `_call_llm_with_context` to:
    - Use retrieved snippets in LLM prompts (when LLM is available)
    - Format snippets into readable responses when no LLM is available
  - RAG store initialized at module load time

- **`requirements.txt`**:
  - Added `scikit-learn==1.3.2` (required for TF-IDF)
  - Added `sentence-transformers==2.6.1` (optional, for better embeddings)
  - Added `faiss-cpu==1.7.4` (optional, for faster search)

- **`README.md`**:
  - Replaced hardcoded agent documentation with RAG explanation
  - Added architecture diagram and example queries
  - Documented two modes (local TF-IDF vs. LLM-augmented)

## How It Works

### Step 1: Index Building (on agent startup)
```
DataStore (JSON files)
    ↓
Document creation (2993 total: 500 companies + 1500 contacts + 493 deals + 500 emails)
    ↓
Vectorization (TF-IDF or sentence-transformers)
    ↓
Index (FAISS or sklearn distance matrix)
```

### Step 2: Query Processing (user asks a question)
```
User query: "What companies are in Technology?"
    ↓
RAG semantic search → [Top-K similar records]
    ↓
If LLM available (OpenAI/Groq):
    Send query + snippets → LLM → Natural answer
Else:
    Format snippets → Readable response
```

### Step 3: Response
```
You: "What companies are in Healthcare?"
Agent: **Companies found:**
  - Burnett-Stafford (Healthcare, 2000 employees)
  - Short-Rivers (Healthcare, 2000 employees)
**Contacts found:**
  - Alice Johnson: VP Sales (C-Level)
  - Bob Smith: Solutions Architect (Manager)
```

## Usage

### Local mode (no API keys needed)
```powershell
python -m app.chat
# Ask any question — responds using TF-IDF semantic search + formatted results
```

### LLM-augmented mode (optional)
```powershell
# Add to .env:
OPENAI_API_KEY=sk-...
# or
GROQ_API_KEY=gsk-...

python -m app.chat
# Same interface, but responses are generated by LLM with context
```

1. **No more rule updates** — Ask any question; RAG finds relevant data automatically
